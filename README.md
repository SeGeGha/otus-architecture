# Сервис планирования путешествий

> **Учебный проект.** Разрабатывается в рамках курса OTUS «Микросервисная архитектура». Кода в репозитории нет и не планируется — только архитектурная документация (сценарии качества, диаграммы C4, ADR), которая растёт вместе с проектом.

## О проекте

Сервис планирования путешествий — платформа для совместного построения туристических маршрутов. Несколько пользователей одновременно создают и редактируют один маршрут в реальном времени, с поддержкой офлайн-режима и полной историей изменений.

Чтобы не уйти в разнос при проектировании, периметр темы сознательно ограничен тремя пунктами:

1. агрегация геоданных из нескольких внешних сервисов — первичные данные для маршрутов;
2. создание и редактирование маршрута;
3. надстройки над (2): аудит/откат/восстановление состояния, деградация и конфликт-резолвинг при синхронизации, офлайн-режим.

MVP-стратегия: сначала агрегация геоданных плюс одиночное (без совместного редактирования) создание маршрута. Совместное редактирование и офлайн-режим — отдельные контексты поверх ядра.

## Драйверы архитектуры

Не весь список фич, а несколько архитектурно значимых требований:

- **D1 — Агрегация геоданных от внешних провайдеров.**

Данные о местах (достопримечательности, отели, рестораны и др.) приходят из нескольких внешних сервисов, каждый — со своим протоколом, форматом и SLA, которые мы не контролируем и не можем изменить. Система должна уметь агрегировать разнородные источники, при этом поддерживать высокую скорость ответа и продолжать работать в деградированном режиме, если один из провайдеров недоступен.

- **D2 — Офлайн-режим с последующей синхронизацией без потерь.**

Сервис не должен «умирать» при потере интернета. Пользователь продолжает редактировать маршрут без сети; при восстановлении соединения изменения синхронизируются автоматически и без потерь.

- **D3 — Полный аудит, откат и восстановление состояния маршрута.**

Любое изменение маршрута должно быть прослеживаемо (кто, когда, что изменил), с возможностью отката к произвольной прошлой версии.

- **D4 — Высокая интерактивность и коллаборация в реальном времени.**

Пока один пользователь двигает точку на карте, второй должен видеть это здесь и сейчас. Если изменения будут приходить с задержкой > 1 секунды или блокировать экран, совместная работа потеряет смысл. Система должна уметь применять параллельные правки без блокировок и без центрального координатора, автоматически разрешать конфликты одновременного редактирования и доставлять изменения всем участникам максимально быстро.
